# 成交后窗口批量复盘

命令入口：

```text
python holding_window_metrics.py --input fill_windows.json --calendar calendar.json --asof 2026-09-09T15:05:00+08:00 --output valuation_20260909.json
```

文件名仅为示例；未提供真实成交，不会自动建仓。input为JSON列表，每条包含fill、bars、costs；calendar为带来源与可用时间的交易日历。输出使用独占创建，重复路径拒绝覆盖，并记录输入文件、日历和计算代码哈希。

fill字段：code、kind（paper_confirmed_fill或user_confirmed_fill）、evidence_id、source、filled_at、available_at、price、shares、price_basis。price_basis目前仅支持显式声明unadjusted_no_corporate_action。成交证据ID不能重复；模块按调用方确认处理，未独立核验成交。

bars是同股票收盘记录列表，每条提供code、date、close、source、data_status=verified、observed_at（交易日15:00）、available_at、price_basis。缺价格或尚未可观察的收盘保持未知；全部成交记录留在报告，不因B+2或B+3表现缺失而删去。

costs提供source、assumption_id、effective_from、effective_to、commission、minimum、sell_tax、slippage。费用期必须覆盖估值日，否则该日估值未知。参数须采用相应历史日期和账户假设，不自动认定示例费用适合实际账户。

calendar提供sessions（升序去重的ISO交易日期）、source、data_status=verified、complete=true、available_at。完整性为来源声明，尚需独立核查。

输出分别汇总纸面和用户确认成交的B+1、B+2、B+3平均净估值、正收益比例和未能评估数量，并计算B+2/B+3同时为正的完整观察比例。比例分母为对应字段可观察的成交批次，未观察数量紧邻披露；两个阶段的分母可能不同。

统计单位是成交批次，不是完整交易。一笔交易分多批成交会产生多个记录，因此这些汇总不能直接用作70%完整交易盈利率。完整交易盈利率、账户回撤尚未实现，保持空值。当前接口未按订单累计最低佣金，也未处理部分退出、公司行为、持仓资金流水与逐时净值，这些属于执行账本后续工作。

本轮5项针对性测试通过，包括买入日后的交易日映射、未来数据不可用、费用期、缺失保留、拒绝触板冒充成交，以及批量纸面/实际分离、重复证据和禁止覆盖报告。测试数据均为合成样本，未产生真实持仓或收益报告。
