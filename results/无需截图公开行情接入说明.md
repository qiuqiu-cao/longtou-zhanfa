# 无需截图公开行情接入说明

## 已实现

`public_live_capture_v1.py` 会自动发现最近一次标准化的沪深主板收盘涨停池，覆盖其中全部首板和连板，通过公开 Level-1 行情接口抓取：

- 提供方行情日期和时间；
- 本地接收时间及行情年龄；
- 开盘、最新、最高、最低、买一、卖一和昨收；
- 累计成交量、累计成交额；
- 10% 涨停价代理、是否处于涨停价代理；
- 当前股票名册覆盖范围内的上涨/下跌家数及涨跌停数量代理。

每个时点固定先抓候选、记录候选响应接收时间，再抓候选以外的市场广度。候选是否按时、新鲜只按第一阶段响应判断，因此全市场约3000只报价的耗时不会把关键候选拖成迟到数据；市场广度另按完整抓取结束时间判断。

`public_minute_capture_v1.py` 在09:35和10:00追加公开1分钟OHLCV，并按事前固定公式生成：

- 5/15分钟VWAP斜率代理；
- 最新价相对当日累计VWAP的位置；
- 首次回落分钟及其相对前3分钟中位成交量；
- 触及涨停的独立分钟段、触板未封分钟数及两次炸板代理；
- 从开盘起算的分钟回封时间；
- 跌破VWAP同时末两分钟成交量较前两分钟放大25%的风险代理。

一分钟内发生但未保留在分钟高低收的数据仍可能丢失，因此以上字段均标记为 `INFERRED_FROM_PUBLIC_1MIN_BARS`。

每次采集都会生成独立、不可覆盖的目录和 SHA-256 摘要，路径为：

`results/v16/public_live/交易日/时点/采集ID/`

## 数据状态

- `VERIFIED_PUBLIC_QUOTE_FRESH`：行情带提供方时间戳，与接收时间相差不超过15秒。
- `DELAYED_PUBLIC_QUOTE`：同一交易日，但延迟超过15秒且不超过120秒。
- `STALE_PUBLIC_QUOTE` 或 `STALE_PREVIOUS_SESSION`：不能用于盘中判断。
- `CASH_PUBLIC_DATA_INCOMPLETE_OR_NOT_ON_TIME`：候选缺失、行情过期、周末、采集时点错误或接口不完整，系统自动空仓。
- `CONDITIONAL_PUBLIC_PRICE_FRESH`：候选价格层完整且及时，但仍只是条件观察。

## 为什么公开行情不能直接产生 ENTER

公开 Level-1 行情可以替代截图中的价格层，却不能验证真实竞价撤单、逐笔主动买卖、Level-2封单队列、排队顺序、部分成交和真实回封过程。即使价格时间戳新鲜，本层也固定 `direct_entry_authorized=false`，只允许：

- `WATCH_PUBLIC_PRICE_ONLY`
- `WATCH_AT_LIMIT_BUYABILITY_UNKNOWN`
- `WATCH_OVERHEATED`
- `CANCEL_WEAK_OPEN`
- `CASH_DATA_NOT_FRESH`

这不是降低龙头战法的进攻性，而是避免把“已经涨停”误判为“现在还能买到”。只有券商/终端可核验的竞价、分钟/逐笔和真实成交链接入后，才有资格进入完整 `ENTER` 审核。

## 使用

候选和市场广度一起抓取：

```powershell
D:\python\python.exe public_live_capture_v1.py --trade-date 2026-09-07 --asof 09:25
```

只抓昨日涨停候选，降低延迟：

```powershell
D:\python\python.exe public_live_capture_v1.py --trade-date 2026-09-07 --asof 09:35 --no-breadth
```

支持的固定时点为 `09:20`、`09:24:50`、`09:25`、`09:30`、`09:35`、`10:00`。省略 `--asof` 时按本地上海时间自动选择最近时点，但迟到采集仍会保留并自动降级，不会伪装成按时证据。

交易日开盘前启动一次，自动发现最新盘后复盘、采集六个时点，并在09:25、09:35、10:00生成决策报告：

```powershell
D:\python\python.exe public_live_monitor_v1.py --trade-date 2026-09-07
```

为避免临盘误用旧候选，建议先运行V135统一入口。它会先显示已经形成的情绪锚、潜在最高标、次高挑战者、首板/连板数量、盘后日期绑定和仍可采集的时点；只有盘后池未过期才允许启动监控：

```powershell
D:\python\python.exe auction_monitor_entry_v135.py preflight --trade-date YYYY-MM-DD
D:\python\python.exe auction_monitor_entry_v135.py start --trade-date YYYY-MM-DD
```

9:20前启动为完整六时点序列；迟到启动只采集仍未错过的时点，已错过时点永久登记为`MISSED_REGISTERED_WINDOW`，不会用后续行情回填。V135仍只生成公开证据和条件判断，不自动下单。

如果不希望自动发现，可增加 `--review 盘后review.json路径 --candidates 全池CSV路径`；只采集行情时使用 `--capture-only`。自动监控会把错过、失败和完成事件逐条写入 `results/v16/public_live_monitor/交易日/运行ID/events.jsonl`，并用前一事件哈希串联。每个有效决策报告位于同一运行目录下的 `decisions/0925`、`decisions/0935` 和 `decisions/1000`。该进程只有在本机实际启动并存活时才叫“正在监控”；仅存在脚本不等于已经启动实时监控，也不会自动下单。

系统还会读取 `data/v3/market_emotion.csv` 的已归档交易日，要求盘后复盘与候选池的信号日同时等于交易日前最近一个已归档交易日。数据没有更新时直接拒绝启动，避免拿更旧的涨停池做当天竞价判断。

运行后验签：

```powershell
D:\python\python.exe public_live_monitor_v1.py --verify-manifest results\v16\public_live_monitor\交易日\运行ID\manifest.json
```

验签覆盖事件顺序、事件哈希、候选/复盘/交易日历、报价与分钟清单、三份决策及报告文件。结论为 `LOCAL_TAMPER_EVIDENT_ONLY`，能发现本地事后修改，但不等于交易所或第三方时间戳。

累计前向采集审计：

```powershell
D:\python\python.exe public_forward_audit_v16.py
```

审计不会挑选同一交易日里结果最好的一次运行；同日多次运行直接标记为不合格。公开层的空仓、取消和观察都保存，但均不计为成交或盈利。当前真实审计为1次V16.4运行验签通过、0个完整交易日、0笔完成交易，完整交易盈利率仍不可计算。

## 导入同花顺/券商委托与成交

按 [委托模板](../templates/broker_orders_v16.csv) 和 [成交模板](../templates/broker_fills_v16.csv) 保留或映射导出字段，然后运行：

```powershell
D:\python\python.exe broker_execution_import_v16.py --decision results\v16\public_live_monitor\交易日\运行ID\decisions\0935\decision.json --orders D:\导出\当日委托.csv --fills D:\导出\当日成交.csv --captured-at 2026-09-07T15:10:00+08:00
```

系统区分 `STRATEGY_COMPLIANT_FULL_FILL`、`STRATEGY_COMPLIANT_PARTIAL_FILL`、`NO_FILL_FINAL`、`NO_FILL_OR_PENDING_UNRESOLVED` 与 `USER_EXECUTION_OFF_PLAN_NOT_STRATEGY_SAMPLE`。当前公开决策固定不授权ENTER，所以基于公开层自行下单即使真实成交，也只能记为用户实盘的非策略合规交易，不会反向计入模型胜率。

## 导入卖出并闭合完整交易

卖出前必须把三种持股情景和最晚B+3时间止损冻结到退出计划；可从 [退出计划模板](../templates/frozen_exit_plan_v16.json) 开始。卖出后运行：

```powershell
D:\python\python.exe broker_exit_import_v16.py --entry-report results\v16\broker_execution\买入日\导入ID\report.json --exit-orders D:\导出\卖出委托.csv --exit-fills D:\导出\卖出成交.csv --exit-trade-date YYYY-MM-DD --exit-plan D:\计划\冻结退出计划.json --exit-confirmations D:\证据\退出触发.json --sessions data\v3\market_emotion.csv --captured-at YYYY-MM-DDT15:10:00+08:00
```

程序检查T+1、累计卖出数量、冻结时间、退出规则窗口、触发证据、未成交、部分卖出及全部买卖费用。跌停或停牌导致无法卖出时必须在退出证据中保留可核验的 `sell_blocked` 状态，仓位继续未解决，不得按计划止损价虚构卖出。

把盘后复盘、09:35公开报价和一分钟证据合并为一份决策报告：

```powershell
D:\python\python.exe live_decision_bridge_v1.py --review results\daily_review_20260904_v3\review.json --quote-manifest results\v16\public_live\2026-09-07\0935\采集ID\manifest.json --minute-manifest results\v16\public_minute\2026-09-07\0935\采集ID\manifest.json --output results\v16\live_decision_20260907_0935_v1
```

桥接器会校验候选池是否完整、交易日/时点是否一致以及输入文件 SHA-256；随后分别列出首板与连板的报价状态、开盘缺口、VWAP代理、炸板/回封代理和硬风险。公开源没有真实委托队列和成交回报，因此结果上限是 `WATCH_PUBLIC_EVIDENCE_ONLY` 或 `WATCH_AT_LIMIT_BUYABILITY_UNKNOWN`，不能承诺涨停价一定买入，也不能承诺次日溢价。
