# 仓位与题材暴露审计说明

## 用途

`risk_budget_audit.py` 只审计已冻结交易预案是否超过用户事先给定的风险上限，不根据个股强弱反推建议仓位，也不把“最强”等同于“可重仓”。审计结果已并入 `trade_account_ledger.py` 的 `risk_budget_audit` 字段。

## 事先冻结的风险政策

每次纸面交易或用户确认交易前，提供带时间戳和来源的 `risk_policy`：

```json
{
  "policy_id": "risk-202609",
  "source": "user_frozen_policy",
  "data_status": "verified",
  "available_at": "2026-09-07T08:00:00+08:00",
  "single_trade_risk_fraction": 0.01,
  "gross_exposure_fraction": 0.30,
  "theme_exposure_fraction": 0.15
}
```

三个比例分别表示：单笔压力损失占账户权益的上限、全部持仓市值上限、同一题材持仓市值上限。它们必须是用户在入场前冻结的约束，不能看到走势后改写。

## 每份入场预案增加的字段

- `account_equity_at_freeze`：冻结预案时的账户权益。
- `existing_gross_exposure_cash`：本笔成交前已有总持仓市值。
- `existing_theme_exposure_cash`：本笔成交前已有同题材持仓市值。
- `stress_loss_fraction`：预先设定的单股压力跌幅，应包含隔夜跳空和流动性风险的保守假设。
- `max_price` 和 `max_shares`：预案允许的最高买入价和最大股数。
- `theme_id`：可核对的细分题材，不使用“医药”这类过宽标签。
- `equity_snapshot_id` 和 `exposure_snapshot_id`：账户与暴露快照标识，用于防止多份预案共用旧快照而重复占用可用资金。

## 审计逻辑

单笔风险允许的最大股数为：

```text
floor(账户权益 × 单笔风险上限 ÷ (最高买价 × 压力跌幅) ÷ 100) × 100
```

系统同时检查计划股数是否超过该上限、新增仓位后的总暴露和题材暴露是否超限。若多份预案共用同一快照，系统返回 `SHARED_EXPOSURE_SNAPSHOT_CANNOT_AGGREGATE_MULTIPLE_PLANS`，不伪装已经完成组合层聚合。

## 边界

- `verified` 表示输入方声明已核对，不代表系统已向券商独立验证。
- 压力跌幅是前视假设，无法保证次日不核按钮，也无法消除跌停卖不出。
- 仓位合规只是执行门槛，不证明候选股有溢价，不证明策略胜率达到70%。
- 若政策、权益、暴露、题材或时间证据不完整，审计应返回 `UNAVAILABLE` 或 `ISSUES_FOUND`，不能把缺失值当作0。
