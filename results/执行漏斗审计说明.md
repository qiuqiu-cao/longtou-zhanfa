# 执行漏斗审计说明

## 用途

`execution_funnel_audit.py` 把每日流程固定为：

```text
收盘主池候选 → 重点候选/预案 → 开盘触发 → 提交订单 → 部分/完整成交 → 持仓
```

涨停价触及、条件触发、订单提交和成交是四个不同事件，不得互相代替。

命令：

```powershell
D:/python/python.exe execution_funnel_audit.py --input 执行事件.json --output 执行漏斗报告.json
```

## 输入

JSON包含 `manifests`、`decisions`、`confirmations`、`orders`、`fills`、`sessions` 和 `asof`。

- `manifests`：每个评估交易日的全池清单，给出上一交易日、候选总数、母池完整性、来源和时间。
- `decisions`：收盘主池每只股票一条，包含首板/连板分组、`FOCUS/WATCH/REJECT` 状态及可选预案ID。非 `FOCUS` 不得偷带交易预案。
- `confirmations`：只记录 `TRIGGERED/CANCELLED/EXPIRED/DATA_LIMITED/NO_TRIGGER`，带观察、可用、失效时间和证据ID。
- `orders`：必须绑定一条先于订单可用的合法 `TRIGGERED` 证据，并记录整数手订单数量、提交、可用和失效时间。
- `fills`：每笔实际或纸面成交事件，必须晚于订单、不晚于订单失效，并带不重复的证据ID。

`kind` 只能是 `paper` 或 `user_confirmed`，一份报告内不能混用。`verified` 仍是输入方声明，不表示本程序已与券商独立对账。

## 输出口径

- `candidate_count`：全部决策记录，不只统计最后下单的股票。
- `focus_count` 与 `planned_count`：重点候选及已冻结预案数。
- `triggered_count`：有效证据触发的预案数，不是成交数。
- `no_order_after_trigger_count`：触发但未提交订单，不能当未成交或亏损交易。
- `pending/unfilled/partial/full_order_count`：分开未到失效时间的等待订单、已完成观察的零成交、部分成交和完整成交。
- `order_fill_rate`：有任何成交的已完成订单/全部已完成订单。仍在等待的订单不进分母。
- `share_fill_rate`：已完成观察订单中的成交股数/订单股数，因此能显示部分成交程度。
- `executed_plan_count`：至少有一笔有效成交的预案数，不按成交回报条数重复计数。
- `known_cash_day_count/cash_day_rate`：只在当日全池清单完整可验时计算空仓日；缺清单日保持未知。

无效触发、时序倒置成交、超过订单数量、跨交易日成交、纸面/实际混用及重复证据均会让报告返回 `ISSUES_FOUND`。无效订单和成交不进入成交率统计，但它们的问题不会被删除。
