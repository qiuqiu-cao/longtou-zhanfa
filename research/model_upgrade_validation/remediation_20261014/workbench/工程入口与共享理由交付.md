## 减少重复填写

`compact --facts <原事实> --draft <原稿> --output <新共享稿>` 将作者已经写出的理由按原文归并为 `reason_bank`，完整保留逐股方向、采纳决定、角色状态、审阅完成标记和来源。作者可直接复用 `{"$reason":"reason_..."}`；引用只允许出现在理由文本，不能替代方向、状态、时间、行情指标或来源路径。

`expand --compact <作者共享稿> --output <新完整稿>` 展开所有引用，核验原稿／事实绑定、完整候选和真实模型暴露，再执行原论坛／补涨审阅校验；正式稿同时执行十一角色、价量、催化、预期、原完整事实及判断校验和真实时刻门。未审模板仍拒绝，不自动转成 `UNKNOWN`，不自动把 `reviewed` 改成完成。最终 `freeze` 仍完整调用旧流程。

实际15只已完成诊断稿包含156处理由文本，归并为105份共享理由，51处可复用，占32.69%。这个比例衡量重复理由文本，不是审阅步骤减少比例、文件体积减少比例或预测改善。展开后的全部15行与原稿逐字段一致，其他元数据除追加来源绑定外一致；所有方向仍为 `null`，新预测0。

## 命令形式

根交叉核验追加：统一入口另支持`validation-status --output-dir <新目录>`和`qualify-information --output-dir <新目录>`，分别只读检查原前向账本/原120门和现存资料资格，不拟合或抓取。根新增2项转发测试后本入口18项通过；全链111项通过。当前源码的完整15只审阅与共享展开见`../final_delivery/workbench/`，当前执行委托及状态分别在`../final_delivery/execution/`和`../final_delivery/validation/`。先前delivery_final及16项等记录保留，当前验收以根`../final_delivery/verification.json`为准，不覆盖旧输出或旧源哈希。

```powershell
python relay_review_workbench.py prepare --features <原归档> --theme-report <完整题材报告> --mainline-report <独立主线> --compatibility <原兼容政策> --bank <已核股吧来源库> --calendar <官方日历> --pool <完整遮分候选> --relation-bank <父锚关系来源库> --output-dir <新批次目录> --history-dataset <角色历史1> --history-dataset <角色历史2> --mainline-history <主线历史1> --narrative-reviews <叙事核阅稿>
python relay_review_workbench.py compact --facts <facts_with_forum_reasoning.json> --draft <作者稿.json> --output <共享理由新稿.json>
python relay_review_workbench.py expand --compact <作者完成共享稿.json> --output <完整新稿.json>
python relay_review_workbench.py freeze --facts <facts_with_forum_reasoning.json> --judgements <完整新稿.json> --output <新独立登记.json>
python relay_review_workbench.py compare --record <原独立登记.json> --baseline <同日原BASE.json> --outcome-archive <原来源目标结果> --output <新比较.json>
```

`prepare` 默认真实暴露为已看模型；真正新日期未看输出时由作者如实显式传 `--model-exposure MODEL_NOT_REVIEWED_SELF_ATTESTED`，这仍是自报状态，不自动认证盲测。
