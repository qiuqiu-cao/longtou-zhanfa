# 龙头自动识别实施方案

本方案于2026年10月12日实际形成。它是针对“龙头定义有了，但程序不能自行辨别各种龙”的代码诊断和研究设计，不是已训练或已验收的识别模型。

## 已核实的缺口

1. `september_forecast_holdout_v278.py:relay_features`的训练目标是`promoted_next_day`；`is_space_leader`由当日最高连板数计算。前者学习次日晋级，后者描述高度，都不能单独证明题材核心或市场影响力。
2. `leader_identity_evidence_v273.py:judge`已有身份转移规则，但`same_height_active_lead`、`absorption_verified`、`all_rivals_failed`等关键证据由调用方提供。`leader_role_mapper_v146.py`也先要求调用方提供已验证的`competition_identity`和`is_emotion_anchor`。它们还缺少从原始档案到身份事实的自动生成链。
3. 新独立判断入口要求填写`role_hypothesis`，并明确`role_identity_verified_by_this_tool=false`。这保留了独立意见，但尚未构成角色训练真值或自动识别效果。
4. 本批指定的10月9日来源中，完整归档池为62只收盘涨停、11只炸板，其中11只连板候选。73只交易题材归属均为未核状态，11只盘中承接全部未知。后续催化上下文中5只存在限定来源叙事、6只未知，但11只均未认证龙头身份。这里的“未知”不能解释为没有题材、没有承接或不是龙头。

以上检查只覆盖指定入口和本批绑定档案，不能概括所有旧研究都没有身份代码或历史资料。旧档案是供应商归档范围，不是交易所认证的全市场；周末分类和后来取得的正文不能倒填10月9日原知识截止。

## 把名称拆成能计算的证据

建议新识别结果按多个维度记录，兼容旧报告所需的一个“当前主身份”，同时保留辅助身份。高度、换手、题材、周期和反包不应互斥；同一股票可能兼有多个已支持角色。

| 角色 | 程序应自动生成的证据 | 缺失或反例怎么处理 |
|---|---|---|
| 高度/空间标 | 完整指定池内最高板、并列对象、高度差、过去已知高度变化 | 只认证指定池内高度；不能自动升级为情绪龙 |
| 题材/主线龙 | 已核交易题材成员、排除自身后的梯队扩散、同题材相对强度及竞争顺序 | 行业相同不等于交易题材相同；缺成员表则未知 |
| 换手核心 | 实际价格分歧、回封路径、回封耗时、分歧期间相对强弱 | 放量或高换手仅是价量事实；没有盘中路径就不确认承接 |
| 容量/趋势核心 | 同题材成交额份额、流通规模、趋势稳定性、板块相对表现 | 只保留连板池会漏掉不涨停中军；现有来源没有覆盖就说明范围 |
| 卡位/竞争胜出 | 冻结的全部竞争者、双方在同一观察时点的状态、可核实的淘汰与主动走强 | 对手从池中消失不能直接记作失败；对手尚强则仍在竞争 |
| 补涨核心 | 已核高位核心、同题材关系、启动先后、低位同批竞争胜出及对旧核心的依附 | 低位涨停不自动构成补涨；依附关系不能只靠文本命名 |
| 节点/周期核心 | 事前固定的市场阶段转折、同期竞争、主线延续和市场反馈 | 日后涨高不能倒推早期已是周期龙；阶段不明则未知 |
| 穿越核心 | 事前定义的压力事件、事件前身份、跨事件存活及重新领先的时序 | 单日抗跌不能确认穿越；确认只能发生在必要证据已出现之后 |
| 情绪核心 | 个股状态变化与短线生态反馈的先后、相对市场和共同事件的条件比较 | 盘面联动不等于资金因果；缺分钟顺序时只记录跨日联动假设 |

“反包”作为价格路径另栏；“妖股”作为事后描述不当事前训练标签。自动识别必须允许同题材无核心、并列竞争、证据不足和身份失效，不能每天强行选一个龙。

## 可执行的数据链

`已有来源 → 带时间与范围的事实 → 股票/题材/竞争者关系 → 当时角色与证据 → 跨日状态变化 → 独立效果结算`

语言模型负责从已保存正文提取“谁、什么事件、何时、与公司业务有什么关系”，输出原文定位和来源时间。程序负责核对股票、日期、范围，计算相对价量、梯队和竞争路径；判定器消费这些证据。所有字段保留已核、推断、未知，不能把模型生成的“承接好”“有带动”直接写成verified。

首批关系用普通关联表就能表达：股票属于哪个已核交易题材、与谁同身位竞争、补涨依附谁、哪个事件影响谁。先把这些事实和时序做准，不因关系存在就把图模型当作必要方案。

每条输出至少包括：`code`、`observed_at`、`available_at`、`knowledge_cutoff`、`scope_id`、`primary_role`、`auxiliary_roles`、`state`、`supporting_evidence`、`counterevidence`、`missing_fields`、`peer_codes`、`invalidation_conditions`。状态为候选、证据支持、失效或未知；未校准时不输出龙头概率。

次日晋级判断、当前角色、开盘成交限制分别留栏。新角色层的第一阶段不自动改原分数、原前5或生产冻结。

## 本批登记的唯一研究假设

**从已有档案自动生成同题材相对竞争和跨日角色证据，能够减少把高板、放量股或后排误认成核心，并比依赖外部身份布尔值的映射更可复核。**

固定基准：现有证据闸门和角色映射；关键身份事实未实际提供时维持未知。唯一挑战：从绑定原始资料生成身份事实，再供独立角色判定使用。先验证题材核心和换手核心两类；池内高度作为机械事实，其他类型在必要输入满足前继续未知。

本批只完成代码诊断、指定来源覆盖检查和假设登记。没有执行身份分类效果比较，没有训练参数，没有启用影子预测。后续数值模型必须在数据资格通过后，另行冻结准确成员、特征、标签、算法参数、截止、日期分组和原效果门；本设计文件不能替代那份数值协议，也不重跑已经淘汰的挑战。

## 标签与验收

- 当时身份标签：只根据该时点可得资料、按事前定义标注；标注者遮蔽模型输出，争议留未知。人工角色假设不是已核真值，不能把原判定器输出再当真值检验自身。
- 后续路径标签：另存角色保持、竞争胜负及主线延续；按预登记的观察窗口成熟后结算，不能回填当时身份。次日涨停不独自定义“真龙”。
- 保留完整同期竞争对象，包括炸板、被淘汰、后排和未知。容量类若缺不涨停成员，仅认证已有范围，不声明市场级识别完成。
- 输入资格：字段定义、原始来源哈希、实际取得时间、历史成员范围及独立标签全部可重建；晚到材料排除原时点训练。当前11只人工判断和后来的催化补正仅作已见诊断。
- 功能检查：事实生成正确率、错误verified数量、完整候选覆盖、未知原因覆盖和时间泄漏拒绝。少输出未知不能单独算提升。
- 身份效果：分角色Precision、完整正例Recall、F1及覆盖率；候选排序补充Top1/Top3核心命中率，另报把后排判成核心的误报和失效识别延迟。未知保留在完整分母，真值未知单列，不当负例。
- 泛化：按完整交易日组滚动划分，训练标签的成熟时间必须早于验证截止；重叠观察窗口须隔离。同一天股票不能随机分散到训练和测试，也不以同一轮已见案例当盲测。
- 生产：若后续角色特征用于改晋级模型，仍沿原全候选Accuracy、Recall、Precision、F1、覆盖和固定120日前向等门执行；角色指标不能代替原晋级验收。没有校准概率不计算Brier，没有成交证据不报告策略收益。

排序技术可在合格数据上使用按日期和题材分组的学习排序；LightGBM提供`LGBMRanker`及分组接口。这说明接口适配方式，不构成它在本项目已有效的证据。[官方接口](https://lightgbm.readthedocs.io/en/stable/pythonapi/lightgbm.LGBMRanker.html)。时间顺序验证可参考[TimeSeriesSplit官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)，本项目还需额外按交易日组和标签成熟时间隔离。
