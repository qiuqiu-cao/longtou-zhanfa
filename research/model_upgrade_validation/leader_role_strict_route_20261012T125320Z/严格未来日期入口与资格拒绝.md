# 严格未来日期验证入口修复

原入口将STRICT也固定到2025下半年、2026年1—8月及9月，并要求三个旧STRICT段全部通过才可登记未来模型。新形成标签无法合法早于这些旧截止，因此未来合格资料也不能完成接续。

现增加 `plan-strict` 和 `freeze --strict-plan`。历史DIAGNOSTIC三段保持原日期，原协议和原结果未修改。未来严格开发验证使用单独预登记的三个日期段，各段必须是官方交易日、在计划实际形成之后，段间隔离五个官方交易日，并有第五日标签窗口的日历覆盖。新日期不能仅通过改协议字段绕过预登记。

```powershell
D:/python/python.exe leader_role_research.py plan-strict --dataset <合格准备期资料.json> --labels <独立身份标签.json> --fold-spec <三个未来日期段.json> --output <唯一资格及计划.json>
D:/python/python.exe leader_role_research.py freeze --dataset <完整比较资料.json> --labels <完整标签.json> --strict-plan <真正合格的预登记计划.json> --output <唯一新比较协议.json>
```

日期文件只有 `folds`，每项为 `id/start/end`。不能夹带参数、门槛或样本过滤。准备期11类各须有20正20负合格严格标签，并有原晋级真值的正负类。此检查不拟合，也不能代替后续实际五段交叉生成角色特征。

只有资格通过才生成可用冻结计划。加载时重新核对来源哈希、准备期样本、标签形成时间和资格，不接受把未合格状态手改为FROZEN。比较资料必须保留原准备期候选和输入。未来日期段的严格源时间回测仍不等于真实前向；独立120日正式窗口和原晋级门必须另外通过。

模型参数、252窗、每日权重、0.5阈值、五日隔离、2000次5日块抽样、固定种子及原统一验收门均未降低。后续推理要求恰好三个预登记STRICT段全部角色和C2筛选通过，空字典、少一段或冒用旧段均拒绝。
