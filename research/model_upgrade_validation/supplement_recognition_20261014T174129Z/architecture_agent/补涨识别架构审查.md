# 补涨识别架构审查

本附页为只读架构审查。源码哈希、AST调用核对和20项相关现有测试结果保存在`architecture_verification.json`。未采集新数据、未拟合、未编辑共享源码，也未改预测登记。架构修复可增加线索可见性，不等于已经提高晋级预测准确率或确认补涨龙身份。

## 已确认的遗漏链

1. `leader_role_review.py:16`的`prepare`依次调用催化、角色、短线和叙事模块，但没有导入、调用或校验`stock_forum_preread`。全项目Python引用搜索只找到它自己的测试；源码AST核对也没有预读调用。研究README描述的是独立预读CLI后把同一个bank供给角色prepare，不是代码级自动前置。AGENTS关于“在prepare生成题材预读卡”的表述因此比实际实现更强。新日期存在跳过预读而生成完整草稿的路径。

2. 正式`SUPPLEMENT`在`leader_role_engine.py:31`要求`theme`及`dependency`两组；`theme`必须是合格具体主题、至少两成员且声明范围完整。`dependency`在391—396行只接受`same_specific_theme=true`与单一`anchor_code`。跨行业的名称、同音、地域或高位情绪锚连接，即使已经有绑定原文，也不能通过这条门。合成核对：相同资料的same_specific_theme=true接受，false或缺项拒绝。

3. `stock_narrative_review.py:77`已经允许`NAME_NARRATIVE`，但它是股票到主题的审阅关系，没有股票到高位锚的关系类型、竞争锚候选及节点序列。该模块输出没有接到dependency；`stock_short_term_context.py:146/163/218`则只从合格dependency及具体theme读取锚和启动叙事。因此名称主题的“存在”无法转成可审阅的“九阳—百洋补涨关系”卡片。

4. `stock_catalyst_context.py:146`拒绝不在当期完整候选池里的STOCK claim。候选池保护是正确的，但已经断连续板、退出当期连板池的九阳，不能作为另一只完整个股实体进入同一个bank。把九阳塞回预测候选池会破坏同池分母；仅在百洋的原文摘录里出现“九阳”，又不能形成完整锚档案。

5. `leader_role_review.py:174`拒绝必需证据缺失时把正式角色填为非UNKNOWN。这个真值与来源保护应保留。现有通用`role_hypothesis`只有自由文本，缺少强制父锚、链路、不同作者结论、采纳/否决/待核、竞争低位及取消条件字段；线索可以再次在长文中遗漏。

6. 当前typed narrative以主帖`source_published_at`确定是否当日（`stock_narrative_review.py:125`），没有像预读模块那样使用`comment_published_at`。老主帖的新评论、新主帖的未知时间评论可能被归到错误日期。新附层应复用预读模块已经正确的正文/评论分栏与讨论时钟，不继承主帖时间。

## 不应重复修复的部分

“补涨要等父龙断板后才启动”不是当前代码的要求。`dependency`只要求父锚先启动，`dependency_start_after_anchor_break_sessions`允许负值；现有`test_supplement_divergence_can_precede_anchor_break_and_future_break_is_rejected`已经验证：自身10月8日起、父锚10月9日断板时差为−1，仍是CANDIDATE；未来断板日期被拒绝。真实缺口是这条信息没有从跨行业关系进入当前审阅，而非数学时间差需要改正。

另外，原dependency的`anchor_identity_source`仅检查非空，并不由它独立认证父锚核心身份；也没有证明唯一父锚。source-bound JSON表示来源被绑定，不代表所有语义假设已获客观认证。这是添加候选锚图谱时必须保留的区别。

## 最小可落实改动

建议在独立审阅入口新增可重建的`stock_supplement_context`附层，暂不改正式SUPPLEMENT数值头、REQUIRED组或训练真值。

- `leader_role_review.prepare`实际先生成并绑定完整预读投影，再生成补涨关系卡、独立作者草稿。新日期freeze检查同一bank哈希、日期、完整候选、实际形成顺序及实际模型暴露声明。旧compare允许原事实卡缺少新字段，旧冻结仅追加诊断附页。
- 保存独立`contextual_anchors`，锚可来自已保存历史完整候选/主线/日线；锚不变成预测候选，不改变原完整分母。每个锚绑定自己的行情序列和来源，不以帖子声称“龙头”作为角色真值。
- 每只原候选都保留`relation_hypotheses`列表，即使为空也说明未覆盖范围。每条含`anchor_code`、`relation_type`、精确原文双实体span、正文/评论归属、发布/取得/实际审阅时间、reviewer、采纳/否决/待核及理由、支持/反证、替代父锚/替代解释、同位及必要低位竞争者、取消条件。关系类型区分具体产业主题、名称/同音、地域、供应链及情绪周期，不能混成`same_specific_theme=true`。
- 保存自身首板、父锚启动/高度/首次分歧/连续板终止及后续观察节点。节点必须是官方交易日与可核行情，不从今日板数倒推并假定中间均可观察。完整父锚缺项与低位竞争者缺项分别列明，允许启动早于断板和父锚未断板。
- 新作者草稿每股强制填写`补涨关系评估`：线索出现、关系是否与时序相容、反例/竞争、角色假设、次日晋级倾向及执行条件分别评估。使用SUPPORTED/CONTRADICTED/UNKNOWN只说明该子命题证据范围；不得自动同步正式SUPPLEMENT身份或PROMOTE。
- 没有原文明示父锚但存在名字相似时，只生成“名称相似待核”提示；不能获得正向晋级分、父龙认证或可交易身份。公开原文确认的是叙事存在，不是资金因果。

## 四层输出契约

| 输出层 | 可确认什么 | 不能自动推出什么 |
|---|---|---|
| 补涨线索候选 | 名称/跨行业连接被提出，待审查名单更完整 | 真实资金迁移、父锚唯一性、补涨龙 |
| 证据支持的关系假设 | 绑定原文、先后节点、完整竞争及相反证据相容 | 严格独立角色真值或已训练SUPPLEMENT准确率 |
| 晋级预测 | 原/作者/挑战按同池同标签的事前方向与结果 | 实际可买到、收益或核心身份 |
| 执行判断 | 当时一字身份、实际开盘/承接/风险与可成交证据 | 由补涨线索或高分直接认证买点 |

正式角色头继续保留UNKNOWN、严格原时点门、独立标签、五日隔离和OOF要求。不能把百洋晋级这一结果直接改写为SUPPLEMENT真阳；完整正反候选缺少独立身份审阅时，补涨识别Recall也必须保留未知。

## 有意义的验收

第一阶段验收是“漏线索路径修复”：同一完整15池仍15只；百洋显示九阳名称/情绪锚及9→12→13→14节点，而九阳不是新增预测候选；每股无覆盖仍存在；评论时钟不继承正文；未来/晚到来源保留实际取得时间；多锚及共同晋级/共同失败仍可表达；名字相似但无明示关系不能自动认证；删候选、错哈希、改方向、改旧角色均被拒绝。

第二阶段才是效果验收：新日期在展示模型前完整留档候选关系假设与作者晋级判断，成熟后按完整同池报告Accuracy、Recall、Precision、F1、覆盖、分板位/真实一字及补涨观察层的误报、漏判、弃判。角色身份结果和晋级标签分开结算，受限历史样例不冒充新前向或总体提升。

本次20项相关既有测试通过，包含预读全部测试、完整草稿测试，以及补涨启动早于父锚断板、晋级漏判不能自动变成角色漏判、角色输入缺项弃判的保护测试。上述通过是架构核验，不是预测改善。
