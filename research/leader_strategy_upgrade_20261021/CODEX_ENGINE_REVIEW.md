# 计算模块的必要语义要求（针对首版实际源码）

本轮已有实际源码 `leader_emotion_engine.py`，方向正确；接入现有入口前修正以下会直接误导判断的行为：

1. `compute_theme_name_proxy_feedback` 当前把所有同字股票、包括炸板/跌停都放入低位diffusion正向列表。完整67只必须按 `kind` 或 `source_kind` 区分：收盘封住、触板失败、下跌、未知，分别计数/保留成员。外部高标也不能仅凭boards>=3就把失败股当存活锚。盛洋是同线失败反例，不能算低位成功扩散。
2. `compute_market_ladder_emotion` 当前把 `promoted=None` 纳入失败，缺收益时正收率返回0，缺路径时亏损计数也像完整0。新增逐项known/unknown/coverage，完整分母不变；完整队列的精确率在有未知时应为未知，可另列已知成员率和明确标名的全分母下界。收益样本数、开收价格成对已知数必须显示。
3. 所有candidate的代码/日期唯一性、当前事实日期=反馈signal_date、prior_date早于signal_date须核；输出文件不能覆盖源事实或已冻结的原文。重复code不能被dict悄悄覆盖。
4. 缺少`reported_open_count`或`one_price`不能默认0或False。缺boards不能默认为首板；保留UNKNOWN分组与原行，不能因转换异常丢行。
5. 除count还要保留完整同位peer代码/名称、封住/失败/未知状态和股自身时点来源。价格开收路径可用 `(1+收盘涨幅)/(1+开盘涨幅)-1`，名为公开价格代理，不是成交收益；昨日二板样本需实际复现1/7和均值+1.7145%，浙江/福莱收红及慕思高开后大跌并存。
6. 当前函数仅实现名称代理，不可宣称完整题材情绪。如果已有显式绑定题材组可单独消费并标证据/成员范围；没有就显示真题材未绑定，继续保留名称代理。不要用行业同字自动认证真实题材。

必要核验用少量真实反例即可：未知晋级不当失败、缺收益不当0、盛洋失败不当扩散成功、并列首封同位不按代码造先后、原67行不改。新代码不自动加模型分数。

这些行为已写成 `test_engine_contract.py` 的8个必要回归检查，首版实跑有5项失败（未知晋级、失败扩散、缺省值、重复代码、错日期），并列名次/缺首封/真实67池3项通过。请修改后运行此脚本；这不是要求写大量镜像测试，而是直接覆盖会误导选股的反例。
