## 二、 独立源码审查发现与 4 项刚性技术限制

在独立查阅本地 Python 环境中 AKShare `stock_fhps_em.py`（[`D:\python\Lib\site-packages\akshare\stock_feature\stock_fhps_em.py`](file:///D:/python/Lib/site-packages/akshare/stock_feature/stock_fhps_em.py)）的实现源码后，Gemini 提出如下**不可动摇的技术红线**：

### 1. 严禁直接调用 AKShare 封装函数 `stock_fhps_detail_em()`
- **原因**：AKShare 内部实现包含了自动分页循环遍历：
  ```python
  for page in tqdm(range(1, total_pages + 1), leave=False):
      params.update({"pageNumber": page})
      r = requests.get(url, params=params)
      ...
  ```
  该函数在遇到多页数据时会向服务器发起非受控的连续 HTTP 请求，直接违反了本项目“单代码单次严格有界”的协议原则。
- **替代执行方案**：编写独立的单请求抓取脚本，直接向 `https://datacenter-web.eastmoney.com/api/data/v1/get` 发送单次 GET 请求，参数固定为：
  - `reportName`: `RPT_SHAREBONUS_DET`
  - `columns`: `ALL`
  - `pageSize`: `100`（单页单次取全，杜绝分页请求）
  - `pageNumber`: `1`
  - `filter`: `(SECURITY_CODE="{code}")`
  - `timeout`: 10 秒。

### 2. 外部 HTTP 请求硬顶：严格 $\le 4$ 次
- 全批次外部请求总数严格上限为 **4 次**（每只股票严格 1 次）；
- 严禁任何形式的超时自动重试、403/429 绕过重试或跨股票扩散。
- 遇网络错误或无数据，直接记录 HTTP 状态码与异常，状态设为 `UNKNOWN`。

### 3. 保存完整原始响应字节与 SHA-256
- 每次请求的响应 Body 必须以原始字节形式持久化存储（如 `raw/{code}_em_sharebonus.response`）；
- 记录发送时钟、接收时钟与 SHA-256 哈希，杜绝清洗后二次加工篡改。

### 4. 资格裁定决断标准：无虚拟稀释参数则禁止全库盲目修复
这是决定能否利用该源修复 28,503 标签库的**生命线原则**：
- 若结构化数据中**未包含**“差异化分红标志（`IS_DIFF`）”或“虚拟分派参数（如 $0.9937, 0.3975$）”，而仅有股东大会名义分派方案（$1.00, 0.40$）；
- 则**严禁直接用该结构化数据对全量 28,503 样本库进行自动化除权计算与标签重写**！
- 理由：今日在 `688368` 和 `600361` 上已确证，若将名义分派强套于差异化分红股票，会产生新的法定参考价偏差，造成二次误标污染。
